# Security Policy

Security issues should not be reported through public GitHub issues, discussions, or pull requests.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting feature on the affected Wyrmgate repository when it is available. If private vulnerability reporting is not available, contact the Wyrmgate maintainers through the private security contact published for that repository or organization.

Please include enough information to reproduce and assess the issue, such as the affected component or version, prerequisites, reproduction steps, expected versus observed behavior, and potential impact.

Do not include real credentials, access tokens, private keys, personal data, or production secrets in a report.

## Response expectations

Wyrmgate maintainers will triage reported security issues, determine affected versions and mitigations, and coordinate disclosure when appropriate. Exact response and remediation timelines depend on severity, reproducibility, and release constraints.

## Scope

Unless a repository states otherwise, this policy applies to software maintained under the Wyrmgate GitHub organization.
